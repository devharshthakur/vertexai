# Repository guidance

Load the `defaults` skill at the start of every repository task. `ARCHITECTURE.md` covers the request lifecycle, service map, data model, and file storage; `SETUP.md` covers local setup.

## Architecture

- The PRD (`docs/PRD/PRD.docx`; readable `docs/PRD/PRD.html`) defines product scope only; do not adopt its suggested React/Express stack. The `docs/PRD/PRD.md` path used by the defaults skill and some source comments is stale; that file was removed.
- `app/` is the Vue client, `server/` Nitro, and `shared/` Zod schemas/types. Use `@/` for `app/`, `#server/` for `server/`, and `#shared/` for `shared/` (from either side). App component and composable auto-import scanning is off (`components.dirs: []`, `imports.scan: false`); import them explicitly, while Nuxt's own composables remain auto-imported.
- API routes are thin: guard with `requireSession`/`requireRole` (or `optionalSession` for public, session-aware routes), validate with the same `shared/validation` schema client forms use via `parseBody`/`parseQuery`/`parseParam`, delegate to `server/services`, and translate `ServiceError` at the route boundary. There is deliberately no global API auth middleware; it would also intercept `/api/auth/**`.
- Client route middleware is not API protection. Every protected API route must guard itself.
- New tables use UUID primary keys, but foreign keys to Better Auth's `users` stay `text`. Roles, statuses, and difficulty values live in `shared/`, not PostgreSQL enums. Export every schema module from `server/db/schema/index.ts`.
- Uploaded material and submission bytes live outside the checkout under `COURSE_MATERIALS_DIR` (default `~/.local/share/vertexai/course-materials`); PostgreSQL stores metadata only.

## Workflow

- The dev server uses port 5173; Compose PostgreSQL publishes 5433. `pnpm validate` is the full gate: Prettier check, then ESLint, then Nuxt typecheck. Focused checks: `pnpm exec eslint <files>` and `pnpm exec prettier --check <files>`. There is no test runner, test script, or CI.
- `pnpm demo:setup` deletes the Compose project's containers and volumes before migrating and seeding; running it is the approval. It requires the demo assets in `public/videos/<slug>/` (the MP4s are gitignored) and builds its connection from `POSTGRES_*`/`POSTGRES_PORT`, not `DATABASE_URL`.
- `pnpm db:seed` (after migrations) requires the same assets, resets demo account passwords, and signs those accounts out.
- Drizzle reads `DATABASE_URL` and loads `server/db/schema/index.ts`. Generate migrations with `pnpm db:generate`, inspect `server/db/migrations/`, then apply with `pnpm db:migrate` when authorized.
- `server/db/schema/auth.ts` is generated by the Better Auth CLI (`pnpm dlx auth@<installed-version> generate --config server/utils/auth.ts --output server/db/schema/auth.ts -y`). Regenerate after auth config or plugin changes; the versions pinned in `SETUP.md` and `schema/index.ts` drift from installed `better-auth`.
- `pnpm git:merge` fast-forwards `main` and leaves you on it; `pnpm deps:update` commits its dependency bump. Both mutate git state, so run them only with explicit authority.
- Vue files outside `app/components/ui/` get shadcn design-system lint rules; `ui/` is the generated primitive layer and is exempt from those rules.
